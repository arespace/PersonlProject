## 1. 四个功能窗口的完整度

### 1.1 完美闪避 i-frames（F1）

**状态：半可用（C++ 钩子已完成，资产侧未验证）**

**证据**

- 免疫判定已统一收口：[PP_BaseCharacter.cpp#L48](../../Source/PersonalProjectCore/Private/Characters/PP_BaseCharacter.cpp#L48) — `CanBeDamaged()` 检查 `PPTags::Status::Invulnerable`。
- `Status::Invulnerable` 在整个 `Source/` 中**只有这一处引用**，没有任何 C++ 代码授予/移除该 Tag。
- 翻滚本身走 ALS 原生能力，没有 GA：[PP_PlayerCharacter.cpp](../../Source/PersonalProject/Private/Characters/PP_PlayerCharacter.cpp) 中输入处理直接调用 `StartRollingGrounded()`，全工程不存在 `GA_PP_Roll` 的 C++ 类。
- `PPTags.h` 中该 Tag 的注释写的是"由 GA_PP_Roll 的 RollStart/RollEnd Notify 控制"，与"翻滚未走 GA"的实现不一致。

**缺什么**

1. 一个在翻滚蒙太奇指定帧授予/移除 `Status.Invulnerable` 的动画通知（C++ 类或蓝图 AnimNotify）。当前两者都没有 C++ 实现。
2. 翻滚结束/被打断时的兜底移除（若只靠 Notify 的 `NotifyEnd`，蒙太奇被打断会残留无敌）。

**收口成本**：2–4 小时（写 Notify + 在 `A_Als_Roll` 上挂点 + PIE 验证）

**风险**：若资产侧 Notify 已存在但未被本文发现，则实际状态是"可用"。**蓝图/蒙太奇侧无法确认**。

**建议**：补 C++ Notify（`UPP_RollInvulnerabilityNotify`），因为纯蓝图 Notify 无法做"打断兜底"；Tag 的增删都放 C++ 更可控。

**建议**：**补警告 + 归属校验**（最小改动）；自动查找可选（同关卡多 Boss 时自动查找本身就不安全）。
