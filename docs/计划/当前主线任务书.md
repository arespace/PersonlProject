## 2. 为什么收口（P1）在重构（P3/P4）之前

1. **没有可对照的"正常行为"，重构就无法验收**。武器系统当前唯一的装备入口是 `F9` 调试键，正常路径"拾取 → 背包 → 装备"不通。P4.1 把武器外观抽成组件、P4.2 统一装备槽时，验收集合里必然包含"装备后外观与 GA 同步"——这条现在本来就不成立，改完也无法判断是重构引入还是历史遗留。
2. **半成品会被当成基线继续叠加**。计分板无数据源、Boss 场地触发器漏配静默失效、死 Tag 制造错误的阅读预期。先收口等于先把"已知不可用"标成显式状态，重构时才能区分"原本不可用"和"被我改坏"。
3. **收口会产生新的验收锚点**。接通武器链路后，"拾取→背包→装备→切 GA→客户端外观一致"成为 P4 的黄金路径；没有它，P4 只能靠肉眼看模型换没换。
4. **收口本身便宜且可回滚**。P1 总工时 2–3 天，逐子项提交，最坏情况整体 revert；而 P4 一旦在错误基线上动刀，回滚成本是它的数倍。

**一句话**：P1 不是"顺手做的功能"，是给 P4 造验收标准。
