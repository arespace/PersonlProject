#### A1. 装备写入为什么只有一个入口？`EquippedItems` 为什么能取代原来的双轨？

**参考答案要点**

1. 双轨是「配置表里的槽位/武器配置」和「角色上的槽位映射/外观缓存」各存一份，必须靠代码同步，任何一次失败都会不一致。
2. 单轨把武器配置内嵌进 `FPP_ItemInfo`，运行时只保留 `EquippedItems` 一份权威状态。
3. `EquipItemInternal` 是唯一写入口：校验 → 扣背包 → 旧装备回包 → 施加 GE 并存句柄 → 写列表 → 广播 → 通知外观。
4. 删掉双轨后，一致性修复、兼容 RPC、缓存镜像都不需要了；`ad526f6` 净删 591 行。
5. `OnRep_Equipped` 只做客户端表现，不参与权威状态。

#### A2. 同槽换装为什么要先扣新物品、再把旧装备回背包，背包满要整次回滚？

**参考答案要点**

1. 先确认新物品存在并 `RemoveItem`，避免「装备凭空生成」。
2. 旧装备回包失败（背包满）时，必须把刚扣的新物品 `AddItem` 回去，整次换装取消。
3. 卸下旧装备的 GE 用保存的 `EffectHandle` 精确移除，不按 GE 类移除。
4. 任何一步失败都要保证「背包 + 装备列表」保持原状，这是事务式顺序。
5. 这是服务器单写入口的价值：客户端只发请求，不参与中间状态。

#### A3. 为什么属性 GE 的句柄要存进 `FPP_EquippedItem`，而不是卸下时按 GE 类移除？

**参考答案要点**

1. 同一个 GE 类可能被武器、Buff、套装等多个来源施加，按类移除会误删别人的效果。
2. `FActiveGameplayEffectHandle` 标识一次具体施加，卸下时只移除自己那一个。
3. 句柄只在服务端有意义，不需要复制；客户端只关心最终属性和外观。
4. GE 配置为空（纯外观/纯技能武器）时句柄无效是合法状态，不能当错误。
5. 保存句柄让「装备 → 卸下」形成闭环，避免残留属性。

#### A5. 无敌帧为什么不用独立 GE，而是跟随 ALS `Rolling` 加 loose tag？

**参考答案要点**

1. i-frames 的起止由蒙太奇里 `AlsAnimNotifyState_SetLocomotionAction` 的持续时长决定，GE 再定义一次会重复且容易不同步。
2. `UpdateRollInvulnerability` 在服务端跟随 `LocomotionAction == Rolling` 加/移 `Status.Invulnerable`。
3. 伤害入口 `APP_BaseCharacter::CanBeDamaged` 统一读这个 tag，所以任何伤害来源都被挡住。
4. tag 只在服务端维护；伤害判定是服务器权威，客户端不需要本地判定。
5. 这样「动画窗口 = 无敌窗口」，改蒙太奇就是改 i-frames，不需要再改 GE 时长。

#### A6. 五个模块为什么必须单向依赖？UI 的 PlayerController 实现为什么放在 UI 模块？

#### A7. EventBus 为什么是 `GameInstanceSubsystem`？它的边界在哪里？

**参考答案要点**

1. 生命周期跨关卡，UI/任务/战斗在关卡切换后仍能拿到同一总线。

#### A8. 为什么 ASC、Inventory、Quest 挂在 PlayerState，而不是 Pawn？

**参考答案要点**

1. PlayerState 跨 Pawn 生命周期存在；死亡、换角色、重连时数据不丢。

5. 敌人可以把 ASC 放 Character 上，因为敌人没有跨 Pawn 的玩家数据。

#### B1. `GiveAbility` 到 `TryActivateAbility` 之间发生了什么？为什么重复授予会导致一次按键扣两次体力？

4. 项目在 `GiveStartupAbilities` 里先查已有 Spec 再去重。
5. 自动激活由 `UPP_AbilitySystemComponent` 的 `OnGiveAbility` / `OnRep_ActivateAbilities` 负责。

#### B2. 为什么 `PossessedBy` 和 `OnRep_PlayerState` 都要 `InitAbilityActorInfo`？`RemoveAll` 解决什么问题？

#### B3. `Montage_Play` 之后，Root Motion 怎么进入 `CharacterMovementComponent` 并移动胶囊？

**参考答案要点**

1. `UAnimInstance::Montage_Play` 创建 `FAnimMontageInstance`，注册到 AnimInstance，每帧 `UpdateAnimation` 推进。
2. 蒙太奇启用 root motion 后，动画求值输出 root motion delta。
3. 该 delta 交给 `UCharacterMovementComponent`，在 `PerformMovement` 里以 `AnimRootMotionVelocity` / `ApplyRootMotionToVelocity` 参与移动。
4. 如果重定向后 root 轨道没有位移、位移只在 pelvis，动画看着在动，胶囊不动，就会出现翻滚回弹。
5. 修复方向是让目标序列的 root motion 生成到 pelvis，或直接给 root 轨道烘焙位移。

- 引擎：`Engine/Source/Runtime/Engine/Private/Animation/AnimInstance.cpp` 的 `Montage_Play`（L2469）、`UpdateAnimation`（L512）；`Engine/Source/Runtime/Engine/Private/Animation/AnimMontage.cpp` 的 `FAnimMontageInstance::Play`（约 L1480）；`Engine/Source/Runtime/Engine/Private/Components/CharacterMovementComponent.cpp` 的 root motion 段。

#### B7. 属性复制和 RPC 怎么选？`Reliable` 的代价是什么？

5. 改进：Widget 生命周期完全交给 UIManager，HUD 只做创建工厂；或引入 MVVM 框架。

#### C7. 如果要做「装备影响技能」的联机预测，哪些必须服务器权威？哪些可以客户端预测？

**参考答案要点**

1. 权威：背包扣减、装备槽变更、GE 施加、GA 授予/移除、伤害结算。
2. 可预测：UI 即时反馈、动画/蒙太奇、移动、无副作用表现。

4. 预测失败要回滚：物品回背包、GE 移除、GA 移除、UI 回滚。
5. 用请求 ID/版本号关联请求与结果，避免乱序。
