## 4. 每个批次的固定流程

无论哪个批次，都按这 8 步走，顺序不省。

### 4.1 开工声明

```
批次：S?
目标：
前置批次：是否已验收
改动文件（超过 10 个必须拆批）：
需要的蓝图配置：
回滚 commit：
预计理想工时：
```

### 4.2 改前基线

- `git status` 干净，记录 HEAD
- 全量编译一次，记录耗时与 warning 数
- 跑数据校验器，记录错误数
- 涉及资产时备份 `Content`
- 导出本批次会迁移的蓝图属性值

### 4.3 实现

- 只改开工声明里的文件
- 不顺手重构、不重命名无关类、不调格式
- 类名/路径变化先加 CoreRedirects

### 4.4 编译

| 改动 | 方式 |
|---|---|
| 仅 `.cpp` 函数体 | 可用 Live Coding |
| 新增/改 `UPROPERTY`、`USTRUCT`、RPC | 关编辑器全量编译 |
| 类重命名/移动/删除 | 关编辑器 + 重定向 + 全量编译 |

零新增 warning 才进入下一步。

### 4.5 蓝图配置

- 出现「组件类未设置 / 父类加载失败」时**立即停止，不保存蓝图**
- 配置完重新打开蓝图，确认默认值与引脚

### 4.6 PIE 冒烟

按第 5.2 节清单执行；角色批次必须测死亡→复活；联机批次必须双客户端。

### 4.7 审查

- 跑 `_tools/CheckModuleBoundaries.ps1`，必须 0 违规
- 自查：跨模块具体类引用、事件是否退订、是否新增硬编码路径、接口实现是否同步

### 4.8 一次提交

```
refactor(<模块>): <批次号> <一句话目标>
```

一个批次一个 commit；提交后回填批次记录（实际工时、偏差、遗留）。

## 5. 阶段门与回滚

### 5.1 进入下一阶段的条件

- 全量编译通过，零新增 warning
- 数据校验器 0 错误
- 冒烟清单全部通过
- 启动日志无资产加载错误、无蓝图编译错误
- `git status` 干净，批次已提交
- 批次记录已填写

### 5.2 冒烟清单

1. 登录/主菜单
2. 建房/加入，进入大厅
3. 角色列表加载，切换角色，预览正常
4. ServerTravel 进入战斗图
5. 移动、跳跃、视角、冲刺、翻滚
6. 技能释放，耐力消耗与回复
7. 受击、硬直、锁定/解锁
8. 死亡、掉魂、篝火复活、属性回满
9. 拾取、背包、装备/卸下、商店买卖
10. 对话、任务接取/提交/奖励
11. Boss 触发、阶段切换、场地门、结算
12. 返回大厅，输入与状态恢复

### 5.3 必须回滚的情况

- 编辑器启动出现资产父类加载失败，或蓝图大面积「类未设置」
- 确认蓝图属性值丢失（如 `WeaponMeshMap` 变空）
- 核心流程 PIE 崩溃，修复一次后仍复现
- 同一问题连续两次修复失败
- 改动文件超过预估 30%
- 性能相对 S0 基线退化超过 20% 且定位不到单点

### 5.4 回滚动作

1. `git revert` 到批次起点
2. 涉及资产的，从 `_Backups` 整体恢复，不用 git 合并单个 `.uasset`
3. 记录失败原因，拆成更小批次再重来

## 7. 风险速查

| 风险 | 触发批次 | 关键防护 |
|---|---|---|
| 蓝图断引用 | S1/S2/S5 | 先改资产父类再删类；启动日志检查 |
