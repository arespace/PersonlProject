# 输入系统统一方案（Enhanced Input 单轨）

> 状态：方案 · 最后更新：2026-11-10 · 取代关系：无
> 调研范围：`Source/**`、`Config/DefaultInput.ini`、`Content/PersonalProject/Input/**`、`BP_PP_PlayerController`、`BP_PP_PlayerCharacter`、ALS 插件输入资产。
> 方法：代码静态检索 + uasset 名称表读取。**能读出每个 IMC 的按键集合**；UE 5.7 使用未版本化属性序列化，逐条 `IA ↔ 按键` 对应无法从二进制稳定解析，已在文中标注“需编辑器确认”。
> 本文只做调研与方案，**未修改代码、未修改资产、未编译、未提交**。

## 0. 结论先行

**按键层面是 2 套机制并存，注册/处理点有 5 处，另外还有 1 套独立的“输入开关”机制。** 不是“Enhanced Input 加几个漏网之鱼”，而是三件事混在一起：绑定方式、UI 按键路径、输入开关语义。

| # | 体系 / 入口 | 负责什么 | 注册位置 |
|---|---|---|---|
| A | Enhanced Input（ALS 层） | 移动、视角、冲刺、行走、蹲、跳、瞄准、翻滚、布娃娃、旋转模式、视角模式、换肩 | 角色 `SetupPlayerInputComponent`，IMC 在 `NotifyControllerChanged` 加入 |
| B | Enhanced Input（项目层） | 技能 1–5、暂停、HUD、对话、任务、背包 | `APP_PlayerController::SetupInputComponent`，加 3 个 IMC |
| C | 传统 `BindKey` | 锁定 Q、计分板 6、篝火 T | PC 2 处 + 角色 1 处 |
| D | UMG `NativeOnKeyDown` | 对话推进 E / Space / Enter、结算 R | `PP_DialogueWidget`、`PP_SettlementWidget` |
| E | 蓝图直接绑定 | BP 控制器的 `IA_Interact`；BP 角色的 `IA_LevelUpAbility` 与原生 `F` 键事件 | 两个蓝图资产图 |
| F | 输入开关（不是按键绑定） | `UIOnly` / `GameAndUI` / `GameOnly`、`SetIgnoreMoveInput` / `SetIgnoreLookInput` | `UIManager` + 3 处 Widget 直调 |

一句话概括：**玩法按键 = A + B + C + E，UI 按键 = B + D + E，开关 = F**。

核心问题按严重度排序：

1. **暂停菜单被“关输入”锁死**：暂停菜单是 Modal + `bConsumesAllInput`，`UIManager` 会切到 `FInputModeUIOnly`，玩家输入整体不再路由，`IA_Pause` 也一起失效。结果是键盘无法再次关闭暂停菜单，只能点 Resume。这是“关掉输入”和“换一套输入”混用的直接后果。
2. **IMC 里没有 Escape**：`IMC_UIInterface` 可读出的按键集合是 `E / F / I / J / N / Tab`，不含 `Escape`；`[ALS_Bug复盘.md](../复盘/ALS_Bug复盘.md)` 里写的“Esc 暂停”是过期信息。
3. **T 键疑似双重绑定**：`IMC_Abilities` 的按键集合包含 `T`，篝火又用 `BindKey(T)`。若 `IA_Fifth` 映射到 T，按 T 会同时放技能和篝火交互。
4. **F 键疑似双触发**：BP 角色有原生 `F` 键事件，BP 控制器又绑了 `IA_Interact`。若 `IA_Interact` 也映射 F，一次按键会跑两个蓝图逻辑。
5. **输入模式有 3 处绕过 UIManager**：暂停菜单、对话、对话选项各自直调 `SetInputMode(FInputModeGameOnly())`，与栈状态可能互相覆盖。

### 1.5 输入模式与输入栈

`UPP_UIManager::RecalculateInputMode()`（[PP_UIManager.cpp:180-208](../../Source/PersonalProjectUI/Private/Framework/PP_UIManager.cpp#L180-L208)）按 Modal → Overlay 的顺序取栈顶，栈顶 `bConsumesAllInput == true` 时：

| 层 | 输入模式 | 具体行为 |
|---|---|---|
| Modal | `FInputModeUIOnly` | `SetIgnoreMoveInput(true)`、`SetIgnoreLookInput(true)`、`StopMovementImmediately`、显示鼠标 |
| Overlay | `FInputModeGameAndUI` | 清除 Move/Look ignore、显示鼠标、不锁鼠标 |
| 其余 | `FInputModeGameOnly` | `ResetIgnoreInputFlags`、隐藏鼠标、焦点交还 GameViewport |

| Widget | 层 | `bConsumesAllInput` | 实际输入模式 |
|---|---|---|---|
| PauseMenu / Dialogue / DialogueChoice / BuyCount / DeathScreen | Modal | true | **UIOnly** |
| Inventory / Shop / QuestList | Overlay | true | GameAndUI |
| Scoreboard | Overlay | false | 不参与判定 |
| Settlement | Modal | false | 不参与判定 → GameOnly |
| HUDWidget | Gameplay | — | 不参与判定 |

## 2. 冲突与重叠判定

### 2.1 已确认的重叠 / 风险

| 键 | 涉及路径 | 判定 |
|---|---|---|
| `UIOnly` + 任意 IA | Modal 打开后整条玩家输入被切断 | **确定缺陷**：暂停菜单、对话等无法用同一个 IA 关闭；`Escape` 也没映射，键盘恢复只能靠鼠标点按钮 |
| `Escape` | 无任何 IMC 映射 | **确定缺口**：需要新增 `IA_UICancel` |
| `Tab` | `IA_Quest` vs Slate 焦点导航 | **高概率被吞**：GameAndUI 下 Slate 先处理 Tab，Enhanced Input 可能收不到；需 PIE 验证 |
| `F` | BP 角色原生 F 事件 + BP 控制器 `IA_Interact` | **高概率双触发**：取决于 `IA_Interact` 实际键位，需编辑器确认 |
| `E` | `IA_Dialogue` 打开对话 + 对话 Widget 的 E 推进 | 打开时 UIOnly 会挡住 IA，暂时不双触发；但关闭瞬间按住的 E 可能在回到 Gameplay 后立刻再次触发 `Interact()`（未 flush 按键） |
| `T` | `IMC_Abilities` 按键集合含 T + 篝火 `BindKey(T)` | **高概率双触发**：取决于 `IA_Fifth` 的键位 |
| `Q` / `6` | 仅 legacy `BindKey` | 不与 IMC 冲突，但绕过上下文切换：Overlay（背包）打开时仍可锁定 / 看计分板 |

### 2.2 功能重叠

- `IA_Dialogue`（C++，E）与 `IA_Interact`（BP，键位待确认）都在做“交互”，且 `APP_PlayerController::Interact()` 内部已经同时处理 NPC 对话与采集。
- BP 角色的原生 F 键事件用途不明，可能是早期交互占位；必须打开蓝图确认后删除或迁移。
- `IA_LevelUpAbility` 只在 BP 绑定，游离于 C++ 单一入口之外。

### 2.3 设计问题归纳

1. 同一个键可能同时被 IMC、`BindKey`、Widget 三处监听，没有统一的“谁消费”。
2. UI 打开用“关掉输入”（UIOnly）实现，而不是“换一套 IMC”，导致 UI 自己的按键也一起失效。
3. 输入模式有 4 个写入方（UIManager + 3 个 Widget），栈状态和实际 Slate 模式可能不一致。
4. Widget 没有显式 `SetKeyboardFocus`，`NativeOnKeyDown` 是否生效取决于 Slate 当前焦点，行为不稳定。

## 3. 统一方案

### 3.1 目标形态

```
                     ┌─────────────────────────────┐
   App_PlayerController │ RegisterAbilityBindings()    │  IMC_Abilities
   （项目动作唯一入口） │ RegisterUIBindings()          │  IMC_UIInterface
                     │ RegisterSystemBindings()      │
                     └─────────────────────────────┘
                     ┌─────────────────────────────┐
   App_PlayerCharacter │ RegisterLocomotionBindings() │  IMC_Als_Default
   （ALS 动作唯一入口） │ RegisterLockOnBinding()       │
                     └─────────────────────────────┘
                     ┌─────────────────────────────┐
   UPP_UIManager      │ 只决定 EPP_InputContext        │  不直接 SetInputMode
                     │ → PC::ApplyInputContext()     │
                     └─────────────────────────────┘
```

规则：

1. **只允许 Enhanced Input + `BindAction`**。新代码不得出现 `BindKey` / `EKeys::` 直接绑键。
2. **每个 owner 只有一个集中注册函数**：PC 的 `SetupInputComponent` 只调用 3 个分组函数；角色只调用 2 个。
3. **ALS 层不动**：`IMC_Als_Default` 和 13 个 `IA_Als_*` 是插件契约，继续由角色持有；不复制、不改插件资产。
4. **IMC 表达“当前能做什么”，SetInputMode 只表达“鼠标/焦点在哪”**。
5. **UI 开关只有一个写入方**：`UPP_UIManager`。

### 3.3 绑定结构

#### PlayerController：一个入口，三个分组

```cpp
void APP_PlayerController::SetupInputComponent()
{
    Super::SetupInputComponent();
    AddGameplayContexts();      // 只加 IMC，不绑键
    RegisterAbilityBindings();  // 1-5 技能
    RegisterUIBindings();       // 暂停 / HUD / 任务 / 背包 / 计分板 / 取消
    RegisterSystemBindings();   // 对话 / 篝火
}
```

| 函数 | 绑定内容 | 事件 |
|---|---|---|
| `RegisterAbilityBindings` | Primary / Secondary / Tertiary / Fourth / Fifth | `Started` |
| `RegisterUIBindings` | Pause、HUDToggle、Quest、Inventory、UICancel | `Started` |
| | Scoreboard | `Started` → Show，`Completed` → Hide |
| `RegisterSystemBindings` | Dialogue、BonfireInteract | `Started` |

改造后的 `SetupInputComponent` 里不再出现 `InputComponent->BindKey(...)`。

#### PlayerCharacter：ALS 动作 + 锁定

```cpp
void APP_PlayerCharacter::SetupPlayerInputComponent(UInputComponent* Input)
{
    Super::SetupPlayerInputComponent(Input);
    RegisterLocomotionBindings(); // 现有 13 个 IA_Als_* 绑定，保持不动
```

锁定保留在角色侧，因为 `LockOnComponent` 属于角色；关键点是改成 `BindAction`，键位从 IMC 读取，不再有 `FKey LockOnKey`。

### 3.4 输入上下文与 IMC 矩阵

新增枚举（放在 PC 头或 UI 公共头）：

```cpp
UENUM()
enum class EPP_InputContext : uint8
{
    Gameplay,  // 正常战斗
    Overlay,   // 背包 / 商店 / 任务列表：可移动，不可战斗
    Modal,     // 暂停 / 对话 / 购买数量 / 死亡：不可移动，UI 键可用
    FrontEnd   // 大厅 / 登录：无 Pawn
};
```

| 上下文 | IMC 组合 | Slate 模式 | 鼠标 | 移动 | 战斗 | 适用界面 |
|---|---|---|---|---|---|---|
| `Gameplay` | ALS(0) + Abilities(1) + UIInterface(1) | `GameOnly` | 隐藏 | 可 | 可 | 默认 |
| `Overlay` | ALS(0) + UIInterface(1) | `GameAndUI` | 显示 | 可 | **禁止** | 背包、商店、任务列表、计分板 |
| `Modal` | UIInterface(2) | `GameAndUI` | 显示 | **禁止** | **禁止** | 暂停、对话、对话选项、购买数量、死亡屏、结算 |
| `FrontEnd` | UIInterface(2) | `UIOnly` | 显示 | 无 Pawn | 无 | 大厅、登录 |

关键决策：

- **游戏内不再使用 `UIOnly`**。`UIOnly` 只保留给大厅/登录（确实没有 Pawn 要控制）。这样 Modal 的关闭键仍然由 Enhanced Input 派发。
- **Overlay 移除 `IMC_Abilities`**，从而在背包/商店打开时禁止技能与攻击；移动仍由 ALS 提供，符合当前“边看背包边走”的体验。若要彻底冻结角色，把 ALS 也从 Overlay 移除即可（改动一行）。
- **Modal 同时移除 ALS 与 Abilities**，进入时调用一次 `StopMovementImmediately()`，不需要 `SetIgnoreMoveInput` 计数器。
- `IMC_UIInterface` 在 Gameplay / Overlay / Modal 都存在，因此“打开键”和“关闭键”是同一个 IA，不会出现“打开后键失效”。

### 3.5 输入模式切换实现

`UPP_UIManager::RecalculateInputMode()` 只负责算上下文，然后调用 PC：

```cpp
void UPP_UIManager::RecalculateInputMode()
{
    EPP_InputContext Desired = EPP_InputContext::Gameplay;
    if (TopModal && TopModal->DoesConsumeAllInput())       Desired = EPP_InputContext::Modal;
    else if (TopOverlay && TopOverlay->DoesConsumeAllInput()) Desired = EPP_InputContext::Overlay;

    if (APP_PlayerController* PC = Cast<APP_PlayerController>(GetPlayerController()))
    {
        PC->ApplyInputContext(Desired);
    }
}
```

```cpp
void APP_PlayerController::ApplyInputContext(EPP_InputContext NewContext)
{
    if (CurrentInputContext == NewContext) return;
    CurrentInputContext = NewContext;

    UEnhancedInputLocalPlayerSubsystem* Subsystem = /* LocalPlayer 子系统 */;
    if (!Subsystem) return;

    // 1. 先移除本控制器持有的上下文
    for (UInputMappingContext* Context : GameplayContexts) Subsystem->RemoveMappingContext(Context);
    Subsystem->RemoveMappingContext(UIContext);

    // 2. 角色侧移动按需开关
    if (APP_PlayerCharacter* Character = Cast<APP_PlayerCharacter>(GetPawn()))
    {
        Character->SetLocomotionInputEnabled(NewContext == EPP_InputContext::Gameplay ||
                                             NewContext == EPP_InputContext::Overlay);
    }

    // 3. 按上下文重新加入
    switch (NewContext)
    {
    case EPP_InputContext::Gameplay:
        for (UInputMappingContext* Context : GameplayContexts) Subsystem->AddMappingContext(Context, 1);
        Subsystem->AddMappingContext(UIContext, 1);
        break;
    case EPP_InputContext::Overlay:
        Subsystem->AddMappingContext(UIContext, 1);
        break;
    case EPP_InputContext::Modal:
        Subsystem->AddMappingContext(UIContext, 2);
        break;
    case EPP_InputContext::FrontEnd:
        Subsystem->AddMappingContext(UIContext, 2);
        break;
    }

    // 4. 清理残留
    FlushPressedKeys();
    ResetIgnoreInputFlags();
    ApplySlateMode(NewContext);   // GameOnly / GameAndUI / UIOnly + 鼠标光标 + 焦点
}
```

- `APP_PlayerCharacter::SetLocomotionInputEnabled(bool)`：内部对 `InputMappingContext` 执行 `Add/RemoveMappingContext`（priority 0），并记录当前是否已加入，避免重复加。
- 删除 `UIManager` 里的 `SetIgnoreMoveInput(true/false)` / `SetIgnoreLookInput`，避免计数器残留；只在进入 Modal 时 `StopMovementImmediately()`。
- 删除 3 个 Widget 内的 `SetInputMode(FInputModeGameOnly())`，统一走 `PopWidget` / `UIManager`。
- `FrontEnd` 仍由 `LobbyHUD` 调 `UIOnly`，但建议同样经由 `ApplyInputContext(FrontEnd)`，保证唯一写入方。

### 3.6 防“按键被吞”与“UI 状态残留”规则

1. **所有游戏内 UI 用 `GameAndUI`，不用 `UIOnly`**。UIOnly 会让 IMC 一起失效，是暂停菜单无法键盘关闭的根因。
2. **Modal 的关闭键必须存在于 IMC_UIInterface**：`IA_Pause`、`IA_ToggleInventory`、`IA_Quest`、`IA_UICancel` 都放在这个上下文里。
3. **每次切换上下文执行 `FlushPressedKeys()`**，避免“E 关闭对话后立刻重新打开”“Shift 卡住冲刺”这类按住键残留。
4. **每次切换执行 `ResetIgnoreInputFlags()`**，不再依赖增减计数。
5. **不要用 Tab 做玩法热键**：GameAndUI 下 Tab 会被 Slate 拿去做焦点导航。若必须保留，给相关 Widget 设置显式导航规则，或把任务面板改回 J。
6. **Widget 需要键盘时显式 `SetKeyboardFocus()`**；更推荐走 `IA_AdvanceDialogue` / `IA_SettlementConfirm` + `UIManager` 转发，彻底移除 `NativeOnKeyDown`。
7. **同一个 IA 禁止同时出现在 C++ 和 BP**；迁移完成前先删旧路径，再启用新路径，避免双重触发。
8. 若后续暂停菜单改为 `SetGamePaused(true)`，相关 IA 必须勾选 `bTriggerWhenPaused`，否则暂停后同样收不到关闭键。
