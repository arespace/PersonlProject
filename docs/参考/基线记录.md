## 3. 编辑器启动日志 Warning 数（已采集，headless 口径）

**步骤**

1. 正常启动编辑器（完整 GUI，不要用 `-unattended` / `-nullrhi`，否则日志不代表真实启动）。
2. 等待 `Output Log` 停止滚动、Asset Registry 加载完成（`Content Browser` 可正常浏览）。
3. 直接读本次启动日志：`Saved/Logs/PersonalProject.log`（每次启动覆盖写入）。

**本次采用 headless 口径**（为避免启停用户的编辑器进程）：

```powershell
& "D:\Ue\UnrealEngine\UE_5.7\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" `
    "d:\Ue\UnrealEngine\program\PersonalProject\PersonalProject.uproject" `
    -unattended -nosplash -nullrhi -nopause -stdout `
    -ExecCmds="Automation List" "-TestExit=Automation Test Queue Empty"
```

## 4. PPMap 平均帧时间（自动化采样）

### 4.1 为什么不用 `-fpschart` 命令行开关

UE 5.7 的实测与源码结论（`Engine/Source/Runtime/Engine/Private/ChartCreation.cpp`、`Engine/Source/Runtime/Launch/Private/LaunchEngineLoop.cpp`）：

- 命令行 `-fpschart` 在 5.7 已不被解析，不会自动开始采样；
- 采样只能由控制台 `fpschartstart` 启动、`fpschartstop` 结束；
- CSV 只在 `UEngine::StopFPSChart` 里写出，**进程退出不会自动 dump**，而 `StopFPSChart` 的唯一调用点就是控制台命令。

也就是说「`-benchmark -fpschart` 跑完自动出报表」在这版引擎上不成立。为此补了一个最薄的包装命令 `pp.FPSChartCapture`（`Source/PersonalProjectCore/Private/Editor/PP_FPSChartCapture.cpp`，`WITH_EDITOR`）：预热 → 启动采样 → 到时自动 stop（落盘 CSV）→ 请求退出。一条命令跑完，不需要第二次敲命令，也不需要人眼读数。

### 4.2 采集命令

```powershell
Get-Process clangd -ErrorAction SilentlyContinue | Stop-Process -Force

& "D:\Ue\UnrealEngine\UE_5.7\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" `
  "d:\Ue\UnrealEngine\program\PersonalProject\PersonalProject.uproject" `
  "/Game/PersonalProject/Maps/PPMap" -game -windowed -resx=1280 -resy=720 `
  -nosplash -nopause -log -stdout `
  -ExecCmds="pp.FPSChartCapture 30 5"
```

- 参数：`pp.FPSChartCapture <采集秒数> [预热秒数] [标签]`，上例为预热 5s + 采集 30s。
- 进程在采集结束后自动退出，无需手动关窗口。
- 采集期间不要启动第二个实例或编辑器；前置条件与第 2 节一致（无并发构建）。
- 需要走固定路线时命令不变：窗口弹出后按路线人工操作，采样照常进行，统计仍由脚本完成（见 4.6 的「路线版」）。

### 4.3 产物位置与命名

```
Saved/Profiling/FPSChartStats/<采集开始时间>/
    PPMap-FPS-WindowsEditor.csv     ← 逐帧数据，解析脚本读这个
    PPMap-FPS-WindowsEditor.log     ← 25/50/75 分位汇总
    PPBaseline-PPMap-<时间>-FPS-WindowsEditor.html
```

- 目录名是采集开始时间，格式 `YYYY.MM.DD-HH.MM.SS`。
- 用编辑器二进制以 `-game` 运行时平台后缀是 `WindowsEditor`（打包版本是 `Windows`）。
- CSV 内含两个区块：分位汇总块（`Percentile,...`）与逐帧块（`Time (sec),Frame (ms), GT (ms), RT (ms), GPU (ms),...`），脚本只读逐帧块。

### 4.4 解析脚本

```powershell
.\_tools\ParseFPSChart.ps1                        # 目录下只有一份采样时才自动使用
.\_tools\ParseFPSChart.ps1 -HitchMs 50            # 自定义 hitch 阈值（默认 33.3ms）
.\_tools\ParseFPSChart.ps1 -Csv <csv路径> -OutFile .\result.md
```

输出 Frame / Game / Draw / GPU 四行的**中位数、P95、最差帧、hitch 次数**，格式可直接粘进本文件。
注意：脚本必须存为 **UTF-8 with BOM**，PowerShell 5 读无 BOM 的 UTF-8 会按 ANSI 解码导致中文报错。

**不带 `-Csv` 时的取数规则**：`FPSChartStats` 下只有一份采样时自动使用；有多份时会列出全部候选并报错，要求用 `-Csv` 显式指定。这是为了避免「按时间取最新」正好取到崩溃或中断留下的残缺 CSV——那份通常是最后一次运行。

### 4.5 失败怎么查

1. 日志搜 `[FPSChartCapture]`：正常应有「已排队」「开始采样」「采样结束」三条，缺哪条就卡在哪一步。
2. 搜 `LogProfilingDebugging: FPS Chart (logfile) saved to`：出现即 CSV 已落盘。
3. `Saved/Profiling/FPSChartStats` 不存在 = 没走到 stop（进程被强杀等），本次作废。
4. 地图加载失败：日志搜 `LogLoad` / `Failed to load`，确认 `/Game/PersonalProject/Maps/PPMap` 可打开。
