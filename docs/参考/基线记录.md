## 2. 全量编译耗时（已采集）

**前置**：关闭编辑器与所有 PIE 窗口；终止 `clangd`（索引进程约占 28 GB 内存，会挤压 UBA 的并行度）；确认没有其它构建进程在跑。

```powershell
Get-Process clangd -ErrorAction SilentlyContinue | Stop-Process -Force

$t = Measure-Command {
  & "D:\Ue\UnrealEngine\UE_5.7\Engine\Build\BatchFiles\Build.bat" `
      PersonalProjectEditor Win64 Development `
      -Project="d:\Ue\UnrealEngine\program\PersonalProject\PersonalProject.uproject" `
      -WaitMutex -Rebuild
}
"耗时: {0:N1} 分钟" -f $t.TotalMinutes
```

> 必须用 `-Rebuild`，不要用 `-Clean`：实测 `Build.bat ... -Clean` 只打印 `Cleaning PersonalProjectEditor binaries...` 就退出，不会接着编译，且残留 143 个 `.obj`，产出的计时没有意义。
> `-Rebuild` 会先删目标二进制与中间对象再完整重编，等价于 clean 全量重编。

**本次实测（2026-11-10，`db0566a`）**

## 3. 编辑器启动日志 Warning 数（已采集，headless 口径）

**步骤**

1. 正常启动编辑器（完整 GUI，不要用 `-unattended` / `-nullrhi`，否则日志不代表真实启动）。
2. 等待 `Output Log` 停止滚动、Asset Registry 加载完成（`Content Browser` 可正常浏览）。
3. 直接读本次启动日志：`Saved/Logs/PersonalProject.log`（每次启动覆盖写入）。

**本次采用 headless 口径**（为避免启停用户的编辑器进程）：

```powershell
& "D:\Ue\UnrealEngine\UE_5.7\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" `
    "d:\Ue\UnrealEngine\program\PersonalProject\PersonalProject.uproject" `
    -unattended -nosplash -nullrhi -nopause -stdout `
    -ExecCmds="Automation List" "-TestExit=Automation Test Queue Empty"
```

- 只用 `-ExecCmds="quit"` 不会退出（卡在编辑器主循环），必须配 `-TestExit` 才会在初始化完成后自动结束。
- **该口径的局限**：不加载启动地图，因此缺少「地图/关卡蓝图加载」阶段产生的 Warning；与真实 GUI 启动的数字可能有差异，后续可在编辑器关闭时补采 GUI 口径做对照。

**计数命令**（排除日志末尾的 `Warning/Error Summary` 汇总块，避免重复计数）

```powershell
$log = "d:\Ue\UnrealEngine\program\PersonalProject\Saved\Logs\PersonalProject.log"
$warnings = Select-String -Path $log -Pattern ": Warning: " |
            Where-Object { $_.Line -notmatch "Warning/Error Summary" }

"Warning 总数: $($warnings.Count)"

# 按日志分类聚合，列出前几名
$warnings |
  ForEach-Object { ($_.Line -split ": Warning: ")[0] -replace '^\[[^\]]+\]\[[^\]]+\]\s*', '' } |
  Group-Object | Sort-Object Count -Descending | Select-Object -First 10 Count, Name
```

## 4. PPMap 平均帧时间（需在 PIE 中采集）

**前置**：单端 PIE（不要开双客户端，避免串行化干扰）；分辨率与画质设置保持默认并在记录里写明；关闭编辑器后台编译与 Shader 编译。

**采集步骤**

1. PIE 进入 `PPMap`，等 HUD 与着色器完全就绪（画面不再卡顿），按 `~` 打开控制台。
2. 输入 `stat unit`（显示 Frame / Game / Draw / GPU 四个毫秒数），再输入 `stat fps` 辅助对照。
3. 按下表路线跑 **3 遍**，每遍约 60 秒，尽量保持相同节奏（不冲刺、不额外战斗）：

   | 段 | 路线 | 时长 |
   |---|---|---|
   | 1 | 出生点 → 直行到最近篝火 | 约 15s |
   | 2 | 篝火处左转 → 走到第一组敌人前 | 约 15s |
   | 3 | 锁定并攻击一次 → 翻滚两次 → 后撤 | 约 15s |
   | 4 | 原路返回出生点 | 约 15s |

4. 每遍结束后立刻记录 `stat unit` 上 `Frame` 的稳定值（取该遍中段的典型读数，不要取加载瞬间的尖峰）；`Game` / `Draw` / `GPU` 一并记录。
5. 三遍取中位数作为本批次基线。

**记录项**

| 项 | 第 1 遍 | 第 2 遍 | 第 3 遍 | 中位数 |
|---|---|---|---|---|
| Frame (ms) | | | | |
| Game (ms) | | | | |
| Draw (ms) | | | | |
| GPU (ms) | | | | |
| 折算 FPS（1000 / Frame） | | | | |

**备注**：`stat unit` 的 `Frame` 是「游戏线程与渲染线程取大并加上同步开销」后的实际帧时间，比 `stat fps` 的瞬时值更稳定，因此以它为准。
