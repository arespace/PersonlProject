# 关卡流程设计（PPMap）

> 状态：现行 · 类型：设计稿（未实施） · 日期：2026-11-11
> 依据：UE 5.7 编辑器中实际加载 `PPMap` / `LobbyMap` 导出的 Actor 清单与坐标；`Source` 现有系统实现；`DT_*` 数据表实际内容。
> 本文只做设计，不改代码、不动资产。坐标单位为米（UE 单位 = 米 × 100）。

---

## 0. 结论

**现状一句话：`PPMap` 不是一张关卡，是一块 200m × 80m 的平地上散放了 14 个玩法 Actor——1 个篝火、2 只小怪、1 个 Boss、4 个采集点（3 个可用）、3 个 NPC、1 扇门、1 个触发盒。没有墙、没有分区、没有近路，出生点到 Boss 只有 24m。打完 Boss 后结算面板只提供“继续”，关掉就无事可做。**

推荐路线（按代价从小到大）：

1. **先补闭环**：结算面板加“返回大厅”，复用现成的 `RequestReturnToLobby`；同时把默认启动地图改成 `LobbyMap`，让“大厅 → 开始 → PPMap → 结算 → 回大厅”真正成立。
2. **再修 Boss 战失败循环**：玩家死亡后门不复位、Boss 不回血，补墙之后会直接卡死；这是必须先修的阻断项。
3. **最后重排关卡**：利用 200m 的长度把出生点、任务 hub、战斗区、Boss 场地重新拉开，全部用现有资产摆放 + 白盒，不新增美术。
4. **不建议现在做**：二周目、真实环境美术、新怪种、新 Boss。

## 1. 摸底：PPMap 现在实际是什么

### 1.1 关卡几何

| 项目 | 实测结果 |
| --- | --- |
| 地面 | 单个 `Floor`，200m（X）× 80m（Y），顶面 Z=0 |
| 导航 | `NavMeshBoundsVolume` 只覆盖 X ∈ [-39.9, 39.7]m、Y ∈ [-39.8, 39.2]m，约 79.5m × 79m |
| 垂直度 | 只有中央一组临时台阶：`Floor2` 4.4m 高台 + `Floor3` 斜坡，位于 (1, -7.7) |
| 墙 / 门 | 没有任何墙体；唯一的门是 Boss 场地的 `BP_BossArenaGate`（2m × 10m × 6m），孤立立在平地上 |
| 光照 | 1 个定向光 + 天空光 + 天空球 + 体积云 + 高度雾，默认模板配置 |
| 玩法 Actor 总数 | 14 个（含玩家出生点、篝火、2 小怪、1 Boss、4 采集点、3 NPC、门、触发盒） |

**关键事实**：因为没有墙，Boss 场地门目前形同虚设——玩家可以从门两侧直接绕过去。一旦补上场地围墙，“死亡后门不复位”就会变成硬卡死（见 1.5）。

### 1.3 现有内容量

- 敌人：小怪 2 只、Boss 1 只、精英 0 只。
- 采集：可用的只有 3 株 `collectedSpecimen`；法力采集点是坏的。
- NPC：3 个（老李、老张、商人），没有铁匠、没有任务板、没有存档点 NPC。
- 任务：4 条，全部围绕老李/老张，**没有一条以 Boss 为目标**。
- 商店：14 件商品，药水 50 金，装备 100–400 金。

任务链实际内容：

| 任务 | 类型 | 目标 | 前置 | 奖励 |
| --- | --- | --- | --- | --- |
| Quest_FindZhang | 支线 | 与老张对话 | 无 | 0 金 |
| Quest_KillThreats | 主线 | 杀 1 近战 + 1 远程 | FindZhang | 100 金 / 50 经验 |
| Quest_PurchaseItem | 主线 | 购买 1 瓶生命药水 | KillThreats | 0 金 |
| Quest_CollectItem | 主线 | 采集 3 个 `collectedSpecimen` | PurchaseItem | 150 金 / 80 经验 |

主线的前置是一个支线，且主线在“采集 3 个标本”后结束，**和 Boss 无关**。玩家把任务清完，Boss 仍然是可打可不打的野外目标。

### 1.4 系统连线（设计要围绕这些，不另造）

| 系统 | 现在的行为 |
| --- | --- |
| 篝火 | 休息 → 记录 `PlayerState` 检查点 + 回满血 + 重置 `ResetRadius` 内所有敌人。**不写档** |
| 死亡 | 掉落 `Gold × 100%` 的魂在死亡点；5 秒死亡界面（实际复活计时 3 秒）；在最近篝火/PlayerStart 复活 |
| 掉魂 | 魂是场景 Actor，靠近 1.4m 自动拾取；再次死亡会销毁上一个魂 |
| Boss 场地 | 门初始开；玩家进入 30×30m 触发盒 → 关门 + Boss 激活；Boss 死亡 → 门开。**玩家死亡不重置门、不重置 Boss** |
| 结算 | Boss 死亡 → 显示 Boss 名/用时/金币，只有“继续”（R） |
| 回大厅 | 暂停菜单“退出” → `RequestReturnToLobby` → `LobbyMap?Listen`（仅主机） |
| 大厅 | `BP_LobbyGameMode`，空景观 + 登录/选角/房间 UI；开始游戏默认去 `PPMap` |
| 存档 | `UPP_SaveSubsystem` 已实现完整读写（属性/背包/任务/检查点/采集点/Boss/掉魂），但**只有控制台 `PP_SaveGame` / `PP_LoadGame` 两个入口**，篝火、结算、退出都不写档 |
| 启动 | `GameDefaultMap=PPMap`，直接进主关卡；大厅只在暂停菜单退出后出现 |

### 1.5 摸底发现的阻断项（按严重度）

| 级别 | 问题 | 证据 | 后果 |
| --- | --- | --- | --- |
| P0 | Boss 战失败后门不复位 | 门只在 `BossDead` 时 `SetOpen(true)`；玩家死亡不触发 | 现在能绕门；补墙后死亡即被锁在场地外，无法再战 |
| P0 | Boss 不回血、不重置 | 玩家死亡流程不调用 Boss 重置；只有篝火休息会 `ResetToSpawn` | 魂类 Boss 战可以靠堆命磨死，失去失败惩罚 |
| P0 | 出生点到 Boss 只有 24m | 出生 (-31,27) → Boss (-37,4) | 玩家 6–10 秒可冲到 Boss，任务链和整张图都可跳过 |
| P0 | 结算没有出口 | `PP_SettlementWidget` 只有 Continue | 打完 Boss 无事可做，闭环缺失 |
| P1 | 篝火 `ResetRadius=10000` | 覆盖全图 | 每次休息都会重置 Boss；想做“局部篝火”必须按实例改半径 |
| P1 | Boss `EnemyID=None` | 实测属性为空 | `DT_Enemies` 的 `Boss_Ancient` 行（200 血/10 伤害/阶段 0.5）完全不生效；结算显示“任意名字” |
| P1 | 采集点 `GatherableID=None` | 4 个采集点全为空 | `DT_Gatherables` 不生效，实际采集 2 秒/次而不是表里的 20 秒 |
| P1 | 法力采集点 `ItemID=None` | `BP_ManaPickup` 实测为空 | 采完不给任何物品，是坏内容 |
| P1 | Boss 金币 500 × 10 = 5000 | `BP_Boss.GoldDropAmount=500`、`BossGoldMultiplier=10` | 商店全部装备合计约 2300 金（单件 100–400），打完 Boss 可直接买空，经济失去张力 |
| P2 | 死亡界面 5 秒 / 实际复活 3 秒 | HUD 硬编码 5s，`RespawnDelay=3.f` | 倒计时与复活不同步（除非蓝图覆盖了 3 秒） |
| P2 | 任务文案损坏 | `Quest_KillThreats`、`Quest_CollectItem` 的显示名是 key 原文 | UI 显示英文 key 而不是中文名 |
| P2 | 导航只覆盖中间 79m | NavMesh 边界实测 | 把内容铺到 200m 全长后，东西两端敌人不会寻路 |

### 1.6 LobbyMap 现状与连接

`LobbyMap` 里没有可玩内容，只有 10 个 Actor：

| Actor | 说明 |
| --- | --- |
| Landscape | 巨幅景观（位置 -1008m，缩放 100），纯背景 |
| PlayerStart | (-2, 0, 0.9)，Yaw 180 |
| DirectionalLight / SkyLight / SkyAtmosphere / VolumetricCloud / ExponentialHeightFog | 默认天空与光照 |
| SM_SkySphere | 天空球 |
| WorldDataLayers / WorldPartitionMiniMap | 世界分区与缩略图 |

- `WorldSettings.DefaultGameMode = BP_LobbyGameMode`，大厅的登录、选角、房间、聊天全部是 UMG，场景本身只是背景板。
- 与主关卡的连接只有两条：`PPMap` 暂停菜单“退出” → `RequestReturnToLobby` → `LobbyMap?Listen`；大厅“开始游戏” → `ServerTravel` 到房间配置的地图（默认 `PPMap`）。
- `GameDefaultMap=PPMap`，所以正常启动根本不会经过大厅；大厅是“退出后才会看到”的隐藏房间。
- 大厅没有“继续游戏 / 新游戏”的区分，也没有读档入口；存档的 `MapName` 字段目前没有被任何 UI 使用。

结论：**大厅已经能用，但它现在不是“家”，只是一个退出后的落脚点。** 要做完整循环，至少要把 `GameDefaultMap` 改成 `LobbyMap`，并给大厅加一个“继续”入口。

## 2. 现状单局循环：玩家实际会怎么走

### 2.1 最短路径：6 秒到 Boss

出生点 (-31, 27) → 场地门 (-27, 7) 约 20.6m → Boss (-37, 4) 约 10.6m。全程约 31m，按跑动 4m/s 计算 **不到 10 秒**。玩家可以完全不碰老李、老张、商人、小怪和采集点，直接打完 Boss 然后卡在结算面板。这是目前“关卡没有流程”的根本原因——不是缺出口，是**没有任何空间或门槛上的顺序**。

### 2.2 任务链的实际路线

如果玩家老实做任务，路线是一个大十字：

| 段 | 距离 | 玩家做什么 |
| --- | --- | --- |
| 出生 → 老李 | 10m | 接 `Quest_FindZhang` |
| 老李 → 老张 | 18m | 对话，交 FindZhang，接 KillThreats |
| 老张 → 东侧小怪 | 64m | 杀 1 近战 + 1 远程 |
| 东侧 → 老张 | 64m | 交 KillThreats，接 PurchaseItem |
| 老张 → 商人 | 22m | 买 1 瓶药 |
| 商人 → 老张 | 22m | 交 PurchaseItem，接 CollectItem |
| 老张 → 东北采集点 | 26m | 采 3 个标本（每个 2 秒） |
| 东北 → 老张 | 26m | 交 CollectItem |
| 老张 → 篝火 | 44m | 休息（可选） |
| 篝火 → 场地门 → Boss | 33m + 11m | 打 Boss |

纯跑动约 **330m / 83 秒**；加上 4 次对话、2 场小战斗、3 次采集、1 场 Boss，**当前全部内容约 5–8 分钟**。其中约 2 分半是重复往返。

### 2.3 问题

1. 任务链和 Boss 完全脱节：清完任务不会引导玩家去打 Boss，打完 Boss 也不结算任务。
2. 采集点、法力点、小怪群集中在东北/东侧两个角落，中间 100m 是空的。
3. 篝火在中心，但离任何内容都不近（到 Boss 33m、到采集点 44m），既不是安全屋也不是捷径。
4. 商人离老张 22m，买药任务强制往返一次。

## 3. 推荐的单局循环（重排后）

目标：**一条 200m 的东→西主线，两个安全屋，三次战斗，一次 Boss，打完能回大厅。** 全部用现有 Actor 重摆 + 白盒墙，不新增美术。

### 3.1 总体结构

```
东（入口） ──────────────────────────────→ 西（Boss）
 Z1 入口营地      Z2 废墟        Z3 中央营地      Z4 祭坛前庭      Z5 Boss 场地
 出生/篝火1/老李   5 小怪/采集1   篝火2/老张/商人   3 小怪+1 精英/采集2   门/触发/Boss
```

- 主轴线：Y ≈ 0，X 从 +78 走到 -85。
- 北侧（Y +15…+35）放采集坡地与可选支路；南侧（Y -15…-35）放精英巡逻和一个小凹槽。
- 安全区（Z1、Z3）不放敌人；战斗区（Z2、Z4、Z5）之间用白盒墙/门框隔开，形成“战斗—喘息—战斗”的节奏。

### 3.2 分区清单（建议坐标）

| 区域 | 范围 (m) | 放什么 | 玩家遇到什么 |
| --- | --- | --- | --- |
| Z1 入口营地 | X 60…85，Y -15…15 | PlayerStart (78,0)、篝火1 (72,5)、老李 (70,12)、2 个白盒箱/帐篷 | 出生即看到篝火与老李；学会休息、接第一条任务；无战斗 |
| Z2 东侧废墟 | X 25…55，Y -25…20 | 3 近战 + 2 远程（错开 8–10m）、北侧 3 株采集、断墙/门框 | 第一次真正的多敌战斗；打完可在北侧顺手采 3 个标本 |
| Z3 中央营地 | X 5…25，Y -15…15 | 篝火2 (18,0)、老张 (12,8)、商人 (8,-6)、法力采集点 (10,-2) | 任务 hub：交任务、买药、休整；商人和老张同处一地，消除 22m 往返 |
| Z4 祭坛前庭 | X -45…0，Y -30…30 | 2 近战 + 1 远程 + 1 精英（巡逻）、南侧 3 株采集、石柱/矮墙 | 精英怪守路；可选南侧凹槽放一个宝箱/额外采集 |
| Z5 Boss 场地 | X -95…-45，Y -25…25 | 围墙、门 (-48,0)、触发盒 30×30、Boss (-85,0)；篝火3 放在门外 (-42,8) | 进门关门，Boss 按 4 段血量（阈值 75%/50%/25%，3 次切换）；死后门开，场地内出现“归途火” |

主线长度：78 → -85 约 163m；算上 Z2/Z4 的侧向绕行约 220m。按 4m/s 纯跑约 55 秒。

### 3.3 逐段体验（玩家视角）

1. **Z1 入口营地**：出生在篝火旁，老李主动给“去找老张”的支线。玩家第一次休息，理解“篝火=检查点+回血+刷怪”。
2. **Z2 东侧废墟**：穿过第一道断墙，遇到 3 近战 + 2 远程的组合；北侧高地有 3 株采集。打完继续向西，发现篝火2。
3. **Z3 中央营地**：老张把支线转成主线（杀怪→买药→采集），商人就在旁边。玩家在这里完成 3 次交任务，不需要长距离往返。
4. **Z4 祭坛前庭**：精英怪（放大的近战，独立 `EnemyID`）挡在主路上；南侧凹槽给一个额外采集/宝箱，作为“探索奖励”。
5. **Z5 Boss 场地**：穿过门框，门在身后关闭，触发盒激活 Boss。Boss 死亡 → 结算 → 门开 → 场地内“归途火”或结算按钮回大厅；如果选择走回去交 Boss 任务，门已经开着，沿主路回 Z3。
6. **闭环**：回大厅后可以“继续”（读档）或“新游戏”。

### 3.4 时长估算

| 阶段 | 预计 |
| --- | --- |
| Z1 教学 + 对话 | 1–2 分钟 |
| Z2 战斗 + 采集 | 3–4 分钟 |
| Z3 任务 hub | 2–3 分钟 |
| Z4 精英 + 探索 | 3–5 分钟 |
| Z5 Boss（含 1–2 次失败重试） | 3–6 分钟 |
| **合计** | **约 15–20 分钟**（熟练玩家 10 分钟，首次 25 分钟） |

## 4. 死亡与掉魂闭环

### 4.1 现在怎么运作（已实测）

- 死亡 → 掉落当前金币 100% 的魂在死亡点（`DeathSoulDropRatio=1.0`）。
- 死亡界面 5 秒倒计时；实际 `RespawnDelay=3 秒`（蓝图未覆盖时）。
- 在最近一次篝火检查点复活；没休息过则回 PlayerStart。
- 复活后敌人保持死亡、Boss 保持当前血量；**只有篝火休息才会重置敌人**。
- 魂靠近 1.4m 自动拾取；再次死亡会销毁旧魂。
- 魂、采集点剩余次数、Boss 击败标记、检查点、背包、任务、属性都已纳入存档结构。

### 4.2 目标闭环

```
篝火休息（写档+检查点） → 探索/战斗 → 死亡（掉 100% 魂）
        ↑                                      ↓
        └── 跑回死亡点捡魂 ←── 在篝火复活（敌人重置）
```

规则建议：

- **保持 100% 掉落**：当前已经是 100%，不需要改。
- **Boss 战失败必须重置 Boss**：玩家死亡时把 Boss 血量回满、阶段清零、场地门重新打开。否则“堆命磨 Boss”会让魂类战斗失去意义。
- **Boss 战失败后复活点放在 Z5 场外篝火3**：跑回场地 ≤ 15 秒，而不是从中央篝火跑 33m。
- **魂不入“篝火重置”**：现在 `ResetEnemiesInRadius` 不会碰魂 Actor，保持现状即可。
- **死亡界面的 5 秒与实际 3 秒统一**：要么把 HUD 改成读 `RespawnDelay`，要么把默认值改成 5 秒（需在编辑器核对蓝图是否覆盖）。

### 4.3 必须补的三个点

| 点 | 为什么 | 代价 |
| --- | --- | --- |
| 玩家死亡 → 重置 Boss + 开门 | 不补就是堆命磨 Boss；补墙后还会锁死 | 小：在玩家死亡/复活流程里对 Boss 场地做一次重置（代码或 Boss 蓝图逻辑） |
| 篝火3（Boss 场外） | 失败重试距离从 33m 降到 10m 内 | 仅摆放 + `ResetRadius` 改小（如 1500） |
| 死亡倒计时同步 | UI 5s / 实际 3s，玩家会觉得“还没数完就活了” | 改 HUD 读值或改默认值，1 处 |

## 5. 打完 Boss 之后：五个方案与取舍

### 5.1 方案对比

| 方案 | 玩家看到什么 | 需要做什么 | 代价 | 风险 |
| --- | --- | --- | --- | --- |
| **A. 结算界面加“返回大厅”** | Boss 死 → 结算面板多一个按钮 → 回大厅 | 改 `WBP_Settlement`，按钮回调复用 `IPP_GameFlowRequest` / `RequestReturnToLobby` | **最小**：1 个 UMG + 1 个已有接口调用，无新 C++ | 回大厅后没有“继续”，再开一局从 PlayerStart 重来 |
| B. Boss 场地内放“归途火” | 场地尽头一团可交互的火/传送门，E 交互回大厅 | 新建 `BP_ExitPortal`（触发器+交互提示+调用 GameMode），或给篝火加“离开关卡” | 小–中：1 个新 BP + 交互提示复用 | 需要处理“休息重置 Boss”；没有存档时和 A 一样是重开 |
| C. 篝火新增“离开关卡”选项 | 走到任意篝火 → 菜单多一项 | 改篝火交互 UMG + 回调 | 小：1 个 UMG + 1 个按钮 | 篝火 `ResetRadius=10000` 会先重置全图，Boss 复活；必须先改半径/顺序 |
| **D. 回大厅 + 大厅“继续游戏”** | 结算 → 自动存档 → 回大厅 → 主界面“继续/新游戏” | 存档触发点（篝火/Boss 死/回大厅）+ 大厅读档入口 + 读档后 `ServerTravel` 到 `MapName` + 应用 `PendingSave` | 中：涉及 UI / GameMode / Save 三处，但 API 都已存在 | 多人大厅要区分主机存档；商店库存未入档 |
| E. 二周目 | 结算 → 更高难度重开 | 难度倍率、敌人配置、UI、存档标记 | 大：新系统 + 数值重做 | 当前内容量撑不起二周目 |

### 5.2 推荐

**推荐 A + D 分两步：先做 A 把闭环补上，再做 D 让“回大厅”有意义。**

理由：

- A 是当前投入产出比最高的一步。`RequestReturnToLobby` 已经存在，暂停菜单已经在用；结算面板只需要多一个按钮，不需要新系统、不需要新资产。
- 只做 A 的缺点很明确：回大厅后再开一局，Boss、任务、采集全部重置，玩家会觉得“白打”。所以紧接着做 D 的最小版本——**Boss 死亡时自动 `SavePlayer`，大厅加“继续”入口**。存档结构已经包含 Boss 击败、采集点、任务、检查点、掉魂，读档后 `SaveSubsystem` 还会自动开门、复活/销毁 Boss、恢复采集点，工作量主要在 UI 和“读档后 travel 到 `MapName`”。
- **B 作为 A 的补充**：有些玩家会先关掉结算面板继续探索，场地内需要一个实体出口。归途火可以复用篝火的模型/特效，只新增一个交互 BP。
- **C 不推荐先做**：篝火休息会重置全图，Boss 会复活；要做对必须先改重置半径和“休息 vs 离开”的顺序，收益不如 A/B。
- **E 暂不做**：目前只有 2 小怪 + 1 Boss + 4 任务，二周目只是把同样的内容再打一遍。

### 5.3 闭环后的完整路线

```
启动 → LobbyMap（登录/选角）
     → 开始游戏 → PPMap Z1
     → Z1→Z2→Z3→Z4→Z5
     → Boss 死亡 → 自动存档 → 结算面板
         ├─ 返回大厅 → 大厅“继续” → 读档回到 Z3/Z5 检查点
         └─ 继续探索 → 归途火/暂停菜单退出 → 大厅
```

**配套建议**：把 `GameDefaultMap` 从 `PPMap` 改成 `LobbyMap`（1 行配置）。否则大厅只是暂停菜单里的隐藏房间，“继续游戏”也没有入口。调试时仍可直接 PIE 打开 `PPMap`。

## 6. 关卡节奏：区域、密度、精英、近路

### 6.1 敌人密度

现状：2 只小怪分布在 200m × 80m 的平地上，等于没有密度。

建议：

| 区域 | 敌人 | 目的 |
| --- | --- | --- |
| Z1 入口营地 | 0 | 安全区，教学 |
| Z2 东侧废墟 | 3 近战 + 2 远程 | 第一次多敌组合，教玩家拉扯/锁定 |
| Z3 中央营地 | 0 | 安全区，任务 hub |
| Z4 祭坛前庭 | 2 近战 + 1 远程 + 1 精英 | 战斗高潮前的压力测试 |
| Z5 Boss 场地 | 1 Boss | 收尾 |

合计 8 小怪 + 1 精英 + 1 Boss。每场战斗间隔 25–40m，符合“跑一段、打一场、喘一口”的节奏。所有小怪都复用 `BP_Enemy_Melee` / `BP_Enemy_Ranged`，通过每个实例的 `EnemyID` 指向不同 `DT_Enemies` 行来调数值，不需要新蓝图。

### 6.2 精英怪

**第一版不需要新美术**：

- 复制一个 `BP_Enemy_Melee` 实例，`EnemyID=Enemy_Elite`，缩放 1.25–1.3，换一个可用的材质实例做区分。
- 在 `DT_Enemies` 增加 `Enemy_Elite` 行：血量约为普通近战的 3 倍、伤害 8、金币 30、`bShouldRespawn=False`。
- 行为仍是现有近战 AI，只是更肉、更疼。这样 Z4 有一个“必须认真打”的目标，但不引入新动画/新技能。

**后续想要真正的精英**（新骨架/新招式）：项目里有 Paragon 英雄/小兵动画资源，可复用模型做新敌人，但需要重定向、动画蓝图和 GAS 配置，属于“新增内容”，不在这次白盒范围内。

### 6.3 近路（shortcut）：现阶段不值得做

原因：

1. 关卡是平的，没有高低差和围墙，任何“近路”都可以直接走过去，做了也没有意义。
2. 当前回头路的主要来源是“商人离老张 22m”。**把商人搬进 Z3 和老张放在一起，比做一扇近路门便宜得多**，收益还更大。
3. 如果按第 3 节重排，主线是单向推进，唯一的回头是“打完 Boss 回 Z3 交任务”。这段路可以靠“Boss 死后门保持开启 + Z5 场外篝火3”解决，不需要额外的门。

如果一定要做，最小方案是：

- 在 Z1 和 Z3 之间放一扇单向门（从 Z3 侧打开，打开后永久开启），复用 `BP_BossArenaGate` 的开门逻辑，新增一个触发器 BP。
- 收益约 20 秒/次，成本约半天 + 1 个新 BP。**建议等关卡有墙、有垂直度之后再做。**

## 8. 与存档的关系

### 8.1 现在保存了什么（已实现）

`UPP_SaveGame`（单槽 `Slot0`）保存：

| 数据 | 内容 |
| --- | --- |
| 角色 | `CharacterId` + 九项属性 base 值（血/蓝/耐/攻/防/回复） |
| 背包 | 物品列表、已装备物品（ItemID + Slot）、金币 |
| 任务 | 进行中任务与计数、已完成任务 ID |
| 检查点 | 是否有检查点、检查点 Transform、篝火 Actor 名 |
| 世界 | 采集点剩余次数、Boss 击败标记（按 `BossName`）、掉落的魂（金额+位置） |
| 元信息 | 存档所在 `MapName`、玩家名、槽位、时间 |

读档时 `ApplyPendingToPlayer` 会恢复属性/背包/任务/金币，并在**同地图**时恢复检查点、采集点、Boss（销毁并开门）、魂。跨地图不会套用关卡级数据。

### 8.2 建议的存档节点

| 节点 | 为什么 | 现状 |
| --- | --- | --- |
| **篝火休息** | 魂类最自然的存档点；玩家预期“休息=保存” | 现在只记录运行时检查点，不写盘 |
| **Boss 死亡** | 回大厅后“继续”必须知道 Boss 已死、门已开 | 不写盘 |
| **提交任务** | 防止回大厅丢任务进度 | 不写盘 |
| **返回大厅前** | 最后一道保险 | 不写盘 |
| 死亡/捡魂 | 魂已经在存档结构里，可选 | 不写盘 |

建议最小政策：**篝火休息 + Boss 死亡 + 返回大厅** 三个自动存档点，其他保持手动/不存。

### 8.3 读档回来玩家应该在哪

- 有检查点：**最近一次休息的篝火旁**（`Checkpoint.Transform`），不是死亡点。
- 没有检查点：`PlayerStart`。
- 存档的 `MapName` 与当前地图不同：先 `ServerTravel` 到 `MapName`，再应用 `PendingSave`。
- Boss 已击败：Boss 不生成，场地门保持开启（现有 `ApplySavedDefeatedState` + `SetOpen(true)` 已实现）。
- 采集点：按 `ActorName` 恢复剩余次数（已实现）。
- 掉落的魂：按存档位置重新生成（已实现）。
- 小怪：**不存档**，读档后全部重生。这是可接受的魂类行为（篝火休息也会重置）。

### 8.4 现有缺口

1. 没有自动存档触发点，也没有存档 UI；只有控制台 `PP_SaveGame` / `PP_LoadGame`。
2. 大厅没有“继续游戏”入口，`MapName` 只存不用。
3. 商店库存不在存档结构里，读档/重进会恢复默认库存。
4. 死亡界面的复活倒计时与 `RespawnDelay` 不一致。
5. 读档恢复 Boss 击败状态时会开门，但**不会重放结算/任务事件**；如果 Boss 任务依赖击杀事件，读档后无法补记。建议 Boss 任务在击杀时立即完成，不要依赖读档补算。

## 11. 风险与待确认

1. **Boss 实际血量未知**：`DT_Enemies` 的 Boss 行未生效，当前血量来自 `GE_InitializeAttributes`，需要在编辑器里确认后再定 Boss 战时长和玩家伤害。
2. **门/触发器的碰撞体尺寸**：门是 2m × 10m × 6m 的孤立碰撞体，补墙前要重新按围墙开口设计，否则会出现“门关了但能绕过去”或“门关了但人卡在门里”。
3. **多人**：大厅最多 4 人，Boss 触发盒按任一角色进入就关门；多人时需要考虑“一人死亡、其他人在场内”的门与 Boss 重置规则。本文按单人优先设计。
4. **存档单槽**：多人/多角色共用 `Slot0`，大厅“继续”只能恢复主机最近一次存档。
5. **重置半径**：`ResetRadius` 是按篝火实例配置的，改小后需要确认“篝火休息只重置附近敌人”符合预期，避免玩家利用篝火刷远处敌人。
6. **白盒风格**：Z1–Z5 用 Cube 拼墙会与现有的天空/雾效风格脱节；这是阶段性方案，最终仍需要真实环境美术。
