# 冒烟清单（Smoke Checklist）

> 用途：每个批次结束、提交前按本清单逐项跑一遍，作为「没有改坏」的固定判据。
> 来源：`docs/计划/架构优化执行计划.md` 附录 B 的 13 条流水，逐条扩写为可判定项。
> 维护：新增玩法或改动已覆盖的系统时，同步在对应小节补一行；不删除历史项，失效项标注「不适用」并写明原因。

**判定规则**

- 「结果」列只允许填 `PASS` / `FAIL` / `N/A`；填写 `FAIL` 必须在备注里写清现象与日志关键行。
- 任一项 `FAIL` 即整批不通过，先定位再决定回滚（回滚判据见执行计划 §3.3）。
- 以下三项与系统基线绑定，每批都要看，不能跳过：
  1. 编辑器启动日志无 `Failed to load Class` / `Failed to load Parent`；
  2. 蓝图编译无报错（编辑器启动后 Output Log 里 `Blueprint` 相关 Error 为 0）；
  3. `git status` 干净（只允许本批次预期内的改动）。

## 前置准备

1. 关闭编辑器与所有 PIE 窗口，全量编译 `PersonalProjectEditor Win64 Development`，确认 `Build succeeded` 且无新增 warning。
2. 打开编辑器，等待资产加载与着色器编译完成（`Output Log` 不再滚动）后再开始。
3. 打开 `Window → Output Log`，把过滤级别设为 `Warning`，清空日志，作为本次观察窗口。
4. 记录当前 HEAD 与批次号到上表。

## 速查：常见 FAIL 的定位入口

| 现象 | 先查 |
|---|---|
| 启动即报 `Failed to load Class/Parent` | CoreRedirects（命名去掉类型前缀）、模块加载顺序、Config 段名 |
| 角色无模型 / 动画为空 | `DT_Characters` 的 Mesh/AnimBP 列、`ApplyCharacterAppearance` 日志 |
| 数据表全部为空 | `Config/DefaultGame.ini` 的 `[/Script/PersonalProjectCore.PP_DataManager]` 段路径 |
| 技能点了没反应 | `IMC_*/IA_*` 是否为 None、GA 是否被重复授予、耐力是否被拦截 |
| 武器不显示 / 卡在脚边 | 武器 socket（`weapon_r`）、`DT_Items` 的 `WeaponConfig.Visual` |
| 面板打开后视角不转 | Widget 的 HitTest 设置、输入模式是否已切回 Game |
